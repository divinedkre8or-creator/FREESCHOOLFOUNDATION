# Free School Gateway

PROJECT: THE FREE SCHOOL FOUNDATION SCHOLARSHIP PORTAL

Build a complete, production-quality scholarship website and applicant management portal for The Free School Foundation.

The platform is being launched initially for The Free School Foundation's partnership with Citi Polytechnic Abuja, providing 100% scholarship opportunities for ND and HND applicants through Citi Polytechnic's Open Distance e-Learning Programme in Aba, Abia State.

This must not feel like a generic school management template.

It should feel like a trustworthy, modern educational opportunity platform built around three experiences:

1. Public scholarship website

2. Applicant portal

3. Foundation admin panel

==================================================

1. BRAND AND VISUAL DIRECTION

==================================================

Use The Free School Foundation as the primary brand.

Use the Foundation's existing visual identity:

- Green

- Orange

- Yellow

- White

The provided scholarship flyer and Free School Foundation logo should guide the visual identity.

However, do NOT recreate the flyer as a website.

Translate the identity into a clean, modern, professional digital experience.

The interface should be:

- Clean

- Human

- Trustworthy

- Accessible

- Mobile-first

- Easy for non-technical users

- Spacious

- Conversion-focused

Avoid excessive gradients, excessive cards, random decorative elements, oversized icons, glassmorphism, generic AI-generated SaaS layouts and unnecessary animations.

Typography should be modern, highly readable and consistent.

The public website should feel aspirational.

The applicant portal should feel simple and reassuring.

The admin dashboard should feel efficient and information-rich without becoming cluttered.

4. APPLICATION SYSTEM

==================================================

Do not create one extremely long application form.

Create a clean multi-step scholarship application experience.

Show progress clearly.

Allow applicants to save their progress and return later.

STEP 1: PERSONAL INFORMATION

Collect appropriate information such as:

- First name

- Middle name

- Last name

- Date of birth

- Phone number

- Email

- Residential address

- State of residence

- State of origin

- Passport photograph

Only collect additional personal information when it has a legitimate application purpose.

STEP 2: PROGRAMME

Applicant chooses:

ND

or

HND

Then chooses:

- Mass Communication

- Business Administration and Management

- Computer Science

- Electrical Engineering

- Computer Engineering

Make the application intelligent.

Questions should adapt depending on whether the applicant selected ND or HND.

STEP 3: EDUCATIONAL BACKGROUND

Collect relevant previous education information.

For ND applicants, collect the appropriate secondary education/result information required for evaluating the application.

For HND applicants, collect their previous ND qualification details, institution, programme studied, graduation year and other relevant qualification information.

Do not unnecessarily collect information that is not needed.

STEP 4: SCHOLARSHIP INFORMATION

Collect:

- Employment status

- Current occupation where applicable

- Reason for applying

- Short response to:

"How will this scholarship help you achieve your educational or career goals?"

Keep written responses reasonably short.

STEP 5: DOCUMENTS

Allow applicants to upload the initial supporting documents required for application.

Keep initial document requirements minimal.

Additional documents should be requestable later from shortlisted applicants through their portal.

STEP 6: REVIEW AND DECLARATION

Display the completed application for review before submission.

Require the applicant to confirm:

"I confirm that the information provided in this application is accurate and complete. I understand that submitting an application does not automatically guarantee admission or scholarship approval and that I may be required to provide additional information or supporting documents during the verification process."

Include separate consent for receiving application-related communication from The Free School Foundation.

After successful submission:

Show a success screen.

Generate a unique application number using a format similar to:

FSF-2026-001284

The applicant should then be able to access their portal.

==================================================

5. APPLICANT PORTAL

==================================================

Create a simple personal dashboard.

An applicant should immediately see:

Welcome, [First Name]

Application ID

Programme Applied For

ND/HND

Application Status

Next Action

Important Messages

Application Timeline

The application journey should support statuses such as:

Draft

Submitted

Under Review

Shortlisted

Additional Documents Required

Approved

Enrolled

Not Successful

Do not expose internal administrative information to applicants.

Applicants should be able to:

- Track their application

- View their submitted application

- See status changes

- Read announcements

- Receive direct portal messages

- Upload additional requested documents

- Update information where permitted

- See outstanding actions

- View communication history relevant to them

Make status explanations human.

For example, don't simply display:

UNDER REVIEW

Explain:

"Your application has been received and is currently being reviewed by our scholarship team."

==================================================

6. ADMIN PANEL

==================================================

This is the operational centre of the platform.

Build a robust but clean admin dashboard.

The dashboard should provide an immediate overview of:

Total applications

Draft applications

Submitted applications

Applications under review

Shortlisted applicants

Approved applicants

Enrolled students

Applications requiring action

Include useful breakdowns by:

ND/HND

Programme

Application status

Application period

The administrator should have a comprehensive applicant management area.

Admins must be able to:

- Search applicants

- Filter applicants

- Open applicant profiles

- Review applications

- Review uploaded documents

- Update application status

- Request additional documents

- Add internal notes

- View status history

- View communication history

- Send individual messages

- Perform appropriate bulk actions

==================================================

7. APPLICANT PROFILE FOR ADMINS

==================================================

Each applicant should have one comprehensive administrative profile.

Organize it clearly into:

Personal Information

Application Information

Programme

Educational Background

Scholarship Responses

Documents

Application Status

Internal Notes

Communication

Activity / Status History

Admins should not have to jump between multiple unrelated screens to understand one applicant.

==================================================

8. COMMUNICATION CENTRE

==================================================

Build a central communication area inside the admin panel.

Admins should be able to communicate with:

- One applicant

- Selected applicants

- Applicants belonging to a particular programme

- ND applicants

- HND applicants

- Applicants with a particular status

- All applicants where appropriate

For the initial version, prioritize:

PORTAL MESSAGES

SMS

The system architecture/interface should also make it easy to introduce email communication later.

Admins should be able to create announcements that appear inside applicant dashboards.

Examples:

Application Deadline Update

Verification Instructions

Document Request

Shortlisting Announcement

Orientation Information

Maintain communication history so administrators can see what was sent and to whom.

Avoid accidental bulk communication.

Bulk communication should clearly show the selected audience and require a review step before sending.

==================================================

9. SCHOLARSHIP MANAGEMENT

==================================================

Although the Citi Polytechnic scholarship is the first programme, do not design the entire platform so that it can only support this scholarship forever.

Create the product concept around scholarship campaigns.

Administrators should eventually be able to manage multiple scholarship opportunities.

Each scholarship campaign should be capable of having its own:

- Name

- Description

- Partner

- Programmes

- Eligibility requirements

- Application opening date

- Application deadline

- Application questions

- Required documents

- Applicants

- Status

- Communications

For launch, however, the Citi Polytechnic scholarship should be the primary and active campaign.

==================================================

10. ADMIN CONTROL

==================================================

Create appropriate administrative roles so access can be controlled.

Not every staff member should automatically have unrestricted access.

The highest-level administrator should be able to manage staff access and determine who can:

- Review applications

- Change statuses

- View documents

- Send communications

- Manage scholarship campaigns

- Manage other administrators

Keep this straightforward and understandable.

==================================================

11. APPLICATION EXPERIENCE

==================================================

Many applicants will access this platform from inexpensive Android phones and mobile data.

Mobile experience is therefore a priority, not an afterthought.

Forms must be extremely easy to complete on mobile.

Avoid horizontal scrolling.

Buttons and inputs should be comfortably tappable.

Uploaded document requirements should be clearly explained.

Never make users wonder whether their application was successfully submitted.

Provide clear:

- Loading states

- Success states

- Empty states

- Error messages

- Validation messages

Save application progress where appropriate.

==================================================

12. TRUST AND PRIVACY

==================================================

This platform handles personal and educational information.

Treat applicant data responsibly.

Only collect information required for legitimate scholarship administration.

Applicant documents and private information must never be publicly accessible.

Applicants must only access their own applications and documents.

Administrative functions must only be accessible to authorized staff.

Do not expose internal notes to applicants.

Do not display sensitive applicant information unnecessarily inside dashboard lists.

Provide appropriate privacy information and applicant consent.

==================================================

13. IMPORTANT PRODUCT PRINCIPLE

==================================================

This platform has two major jobs:

PUBLIC SIDE:

Convince qualified people to apply.

PRIVATE SIDE:

Help The Free School Foundation efficiently process, communicate with and manage those applicants.

Do not sacrifice either side.

The public website should be beautiful and conversion-focused.

The applicant portal should be simple.

The admin panel should be powerful.

Do not over-engineer the visible UI.

The complexity should live behind a straightforward user experience.

==================================================

14. BUILD EXPECTATION

==================================================

Do not build a static mockup.

Build the actual working application.

Every visible action should have a purpose.

Forms should work.

Applications should persist.

Authentication should work.

Applicant accounts should work.

Admin authentication should work.

Statuses should work.

Document uploads should work.

Applicant filtering and searching should work.

Portal messaging should work.

Admin notes should work.

Announcements should work.

Communication history should work.

The responsive experience should work properly across mobile, tablet and desktop.

Use sensible sample data during development so that dashboards and application states can be properly tested.

Before considering the project complete, walk through the entire journey:

Visitor

→ Scholarship page

→ Application

→ Account

→ Submission

→ Applicant dashboard

→ Admin receives application

→ Admin reviews applicant

→ Admin changes status

→ Applicant sees update

→ Admin requests document

→ Applicant uploads document

→ Admin reviews it

→ Applicant gets shortlisted/approved

→ Communication remains recorded.

Approach this as a real scholarship platform that will be used by real applicants and administrators, not as a UI demonstration.
